Fase 5: Visualización + API + BD + ESP32 funcionando de punta a punta

Nota importante

E5 se construye ENCIMA de E4. Mismo firmware, misma API, misma base de datos. Solo agregas visualización y pulas la integración.

Prerrequisitos (de E4)

Para realizar esta evaluación debes tener:

  • Firmware E4: ESP32 con millis(), máquina de estados e histéresis funcionando.
  • API E4: FastAPI (o Flask) con los 3 endpoints y Swagger accesible.
  • BD E4: Tabla de sensores con datos reales provenientes del ESP32.
  • Conectividad: ESP32 y PC en la misma red WiFi local.

Objetivo de E5

Demostrar en clase el funcionamiento integral del sistema: el ESP32 envía datos, la API los recibe y almacena en la base de datos, y una interfaz de visualización muestra los datos en tiempo real o el historial.

Requisitos del Sistema Integrado

Todo lo heredado de E4 debe seguir funcionando, más los siguientes agregados:

  • Firmware (heredado de E4):
    • Multitarea no bloqueante con millis().
    • Máquina de estados (NORMAL, ALERTA_TEMP, ALERTA_LUZ, ALERTA_DOBLE).
    • Histéresis en los cambios de estado.
    • Envío periódico de JSON por HTTP POST (o MQTT).
  • API y BD (heredado de E4):
    • Endpoints POST /datos, GET /datos y GET /datos/latest operando.
    • Base de datos con historial real acumulado (idealmente varios días de datos).
    • Swagger UI visible en /docs.
  • Visualización de datos (nuevo):
    • Una interfaz gráfica que muestre los datos. Opciones (elige una):
      • Página HTML simple con JavaScript que haga fetch() a tu API.
      • Dashboard en Grafana conectado a SQLite/MySQL.
      • Cualquier dashboard web propio que consuma la API.
    • Debe mostrar al menos temperatura, humedad y luz.
    • Debe poder verse el último dato o un pequeño historial.
  • CORS configurado (nuevo):
    • La API debe permitir peticiones desde el navegador donde se abra la visualización.

Entregable

  • Demo en vivo en clase (obligatorio): Cada grupo conecta el ESP32, levanta la API y muestra la visualización funcionando. El profesor puede hacer preguntas sobre el flujo de datos.
  • Código fuente ZIP subido a Canvas: Incluye firmware, API, script de BD y archivos de visualización.

Lista de Verificación Pre-Demo

  • ☐ El ESP32 enciende y se conecta a WiFi
  • ☐ Se ve el log del ESP32 enviando JSON y recibiendo respuesta HTTP 200
  • ☐ La API está corriendo en el PC (FastAPI o similar)
  • ☐ Swagger UI responde en /docs
  • ☐ La BD tiene datos recientes del ESP32
  • ☐ La visualización muestra al menos un valor actualizado
  • ☐ CORS está habilitado si la visualización es web
  • ☐ Código fuente comprimido en ZIP y listo para subir a Canvas
