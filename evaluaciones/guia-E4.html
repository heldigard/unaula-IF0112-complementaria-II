Fase 4: Firmware mejorado + API FastAPI/MQTT + Base de datos

Nota importante

Todo lo que construyan en E4 será la base para E5 y E6. No lo van a rehacer, lo van a mejorar. Construyan bien desde ahora.

Prerrequisitos (de E3)

Para realizar esta evaluación debes tener funcionando:

  • E3 Software: ESP32 enviando datos a la nube cada 20 segundos (WiFi conectado).
  • Código de E3 con estructura no bloqueante usando millis().
  • Python instalado en el PC (Windows) donde correrá la API.

Objetivo de E4

Documentar en un informe técnico el funcionamiento del firmware mejorado junto con una API local básica y una base de datos que reciba los datos del ESP32.

Requisitos del Firmware (heredado + nuevo)

El código fuente actualizado debe incluir:

  • Multitarea Cooperativa (No Bloqueante):
    • Eliminar completamente el uso de delay() en el loop() principal.
    • Usar millis() para gestionar múltiples tareas simultáneas:
    • - Tarea 1: Lectura de sensores cada 2 segundos.
    • - Tarea 2: Envío a la API cada 20 segundos.
    • - Tarea 3: Actualización de LEDs cada 100 ms.
  • Máquina de Estados (State Machine):
    • Definir enum con estados: enum Estado { NORMAL, ALERTA_TEMP, ALERTA_LUZ, ALERTA_DOBLE };
    • Variable de estado: Estado estadoActual = NORMAL;
    • Transiciones basadas en umbrales configurables:
    • - NORMAL: Temp < 28°C y Luz > 30%.
    • - ALERTA_TEMP: Temp ≥ 30°C.
    • - ALERTA_LUZ: Luz ≤ 20%.
    • - ALERTA_DOBLE: Ambas condiciones críticas simultáneas.
  • Histéresis (Zona Muerta):
    • Evitar oscilaciones rápidas de actuadores cuando el valor oscila cerca del umbral.
    • Ejemplo para temperatura: Encender alerta a 30°C, apagar a 28°C (2°C de histéresis).
    • Implementación: Usar dos umbrales separados (umbralAlto y umbralBajo).
  • Envío de datos a API local (nuevo):
    • HTTP POST a la API FastAPI corriendo en tu PC (Windows) en la red local, o publicación MQTT a un broker.
    • Formato JSON estructurado: {"temperatura": 24.5, "humedad": 60.0, "luz": 45.0}.
    • El ESP32 debe enviar periódicamente los datos en este formato.

Requisitos de API y Base de Datos (nuevo)

Debes montar una API local que reciba y almacene los datos del ESP32:

  • Framework: FastAPI corriendo en Windows local (o Python + Flask si prefieres, pero FastAPI es el recomendado).
  • Base de datos: SQLite (recomendado) o MySQL/MariaDB (opcional).
  • Endpoints mínimos:
    • POST /datos → Recibe el JSON del ESP32 y lo guarda en BD.
    • GET /datos → Lista todos los registros almacenados.
    • GET /datos/latest → Devuelve el último registro insertado.
  • Tabla sensores con campos: id, temperatura, humedad, luz, timestamp.
  • Swagger UI: Debe estar accesible en http://localhost:8000/docs (FastAPI lo genera automáticamente).
  • CORS habilitado: Necesario para que en E5 un dashboard web pueda consultar la API.

Tip: Usa el código de ejemplo del curso como punto de partida:

  • codigo/servidor/api/main.py → FastAPI + SQLite completo.
  • codigo/esp32/esp32-http-post-api.ino → Sketch ESP32 con HTTP POST.
  • codigo/servidor/mqtt/subscriber.py → Alternativa MQTT + SQLite.

Estructura del Informe

El documento PDF debe seguir este orden:

  1. Portada + introducción: Explicación del flujo de datos que vas a construir.
  2. Arquitectura del flujo de datos: Diagrama ESP32 → API → BD. Incluye la IP local, el puerto y el formato JSON.
  3. Firmware mejorado: Código completo + explicación del uso de millis(), máquina de estados e histéresis.
  4. API: Listado de endpoints, fragmento del código principal y cómo se ejecuta en Windows.
  5. Base de datos: Schema de la tabla, ejemplo de inserción y consulta, y screenshot de los datos guardados.
  6. Evidencias: Capturas de pantalla de Swagger (/docs), datos en la BD, log del Monitor Serial del ESP32 y la respuesta HTTP recibida.
  7. Conclusiones y problemas encontrados: Qué dificultades tuvieron y cómo las solucionaron.
  8. Sección "Para E5": Qué mejorarían o agregarían (visualización, más endpoints, más sensores).

Lista de Verificación Pre-Entrega

  • ☐ El código tiene 3 tareas concurrentes usando millis() (lectura, envío, LEDs)
  • ☐ La máquina de estados tiene al menos 4 estados (NORMAL, ALERTA_TEMP, ALERTA_LUZ, ALERTA_DOBLE)
  • ☐ Hay histéresis implementada (ej: encender a 30°C, apagar a 28°C)
  • ☐ El ESP32 envía JSON por HTTP POST (o MQTT) a la API/broker
  • ☐ FastAPI corre localmente con los 3 endpoints requeridos
  • ☐ La BD tiene datos reales provenientes del ESP32
  • ☐ Se ve Swagger UI en http://localhost:8000/docs
  • ☐ El informe incluye diagrama de flujo de datos, código, evidencias y sección "Para E5"
  • ☐ Código en GitHub con README actualizado
