Fase 4 del Proyecto SMAI: Gestión domótica e inteligencia del sistema

📋 Prerrequisitos (de E3)

Para realizar esta evaluación debes tener funcionando:

  • E3 Software: ESP32 enviando datos a la nube cada 20 segundos (WiFi conectado).
  • Dashboard en plataforma IoT (Ubidots, ThingSpeak o similar - ver opciones gratuitas) mostrando datos en tiempo real.
  • Código de E3 con estructura no bloqueante usando millis().

Nota: Esta evaluación agrega lógica de control inteligente sobre el código de E3. No se modifica el circuito, solo se mejora el firmware. Este código será la base para E6.

Requisitos del Firmware (Lógica SMAI)

El código fuente actualizado debe demostrar el uso de técnicas avanzadas de programación embebida para IoT. Se construye sobre el código de la E3, agregando inteligencia al sistema:

  • Multitarea Cooperativa (No Bloqueante):
    • Eliminar completamente el uso de delay() en el loop() principal.
    • Usar millis() para gestionar múltiples tareas simultáneas:
    • - Tarea 1: Lectura de sensores cada 2 segundos.
    • - Tarea 2: Envío a la nube cada 20 segundos.
    • - Tarea 3: Actualización de LEDs cada 100 ms.
    • Estructura: if(currentMillis - previousMillis >= interval) { ... }
  • Máquina de Estados (State Machine):
    • Definir enum con estados: enum Estado { NORMAL, ALERTA_TEMP, ALERTA_LUZ, ALERTA_DOBLE };
    • Variable de estado: Estado estadoActual = NORMAL;
    • Transiciones basadas en umbrales configurables:
    • - NORMAL: Temp < 28°C y Luz > 30%.
    • - ALERTA_TEMP: Temp ≥ 30°C.
    • - ALERTA_LUZ: Luz ≤ 20%.
    • - ALERTA_DOBLE: Ambas condiciones críticas simultáneas.
  • Histéresis (Zona Muerta):
    • Evitar oscilaciones rápidas de actuadores cuando el valor oscila cerca del umbral.
    • Ejemplo para temperatura: Encender alerta a 30°C, apagar a 28°C (2°C de histéresis).
    • Implementación: Usar dos umbrales separados (umbralAlto y umbralBajo).
    • Código: if(temp > UMBRAL_ALTO) estado = ALERTA; else if(temp < UMBRAL_BAJO) estado = NORMAL;
  • Condiciones de Entrada:
    • Debe usar el código funcional de la E3 (conectividad WiFi) como base.
    • Los umbrales deben ser configurables mediante constantes al inicio del código.

En esta etapa, el SMAI ya no solo "envía datos", sino que debe "gestionar situaciones". Se evaluará la complejidad de las reglas programadas (uso de lógica booleana y operadores relacionales).
