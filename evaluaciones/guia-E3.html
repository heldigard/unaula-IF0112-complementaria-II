Fase 3 del Proyecto SMAI: Conectividad IoT a través de redes e Internet

📋 Prerrequisitos (de E2)

Para realizar esta evaluación debes tener funcionando:

  • E2 Prototipo: Circuito con ESP32 + DHT22 + LDR leyendo datos correctamente.
  • Código de E2 funcionando: lectura de sensores cada 2 segundos, LEDs respondiendo a umbrales.
  • Monitor Serial mostrando valores de temperatura, humedad y luz en formato legible.

Nota: Esta evaluación NO requiere modificar el circuito de E2, solo agregar conectividad WiFi al código existente. El mismo hardware servirá para E4.

Objetivo

Desarrollar el firmware de conectividad para el SMAI, permitiendo que el microcontrolador ESP32 transmita datos ambientales a una plataforma en la nube a través de protocolos IP.

Requisitos Técnicos del Firmware

El código .ino debe implementar obligatoriamente los siguientes componentes de conectividad IoT:

  • Configuración WiFi Modo Estación (STA):
    • Uso de WiFi.mode(WIFI_STA) para conexión a red existente.
    • Configuración de credenciales: const char* ssid = "nombre_red"; y const char* password = "clave";.
    • Tiempo máximo de intento: 10 segundos antes de timeout.
  • Gestión de Estados de Red:
    • Imprimir en Serial: "Conectando a WiFi...", "WiFi conectado".
    • Mostrar dirección IP asignada: WiFi.localIP().
    • Verificar estado antes de cada envío: if(WiFi.status() == WL_CONNECTED).
  • Protocolo HTTP GET:
    • Uso de librería HTTPClient para envío de datos.
    • URL de ThingSpeak: "http://api.thingspeak.com/update?api_key=TU_KEY&field1=temp&field2=hum&field3=luz".
    • Código de respuesta HTTP 200 = éxito.
    • Liberar recursos: http.end() después de cada envío.
  • Frecuencia de Envío y Temporización:
    • Intervalo: 20 segundos (20000 ms) entre envíos.
    • Uso de millis() para temporización no bloqueante (NO usar delay()).
    • Variable unsigned long lastTime = 0; para control de tiempo.
  • Reconexión Automática:
    • Detectar desconexión: if(WiFi.status() != WL_CONNECTED).
    • Reintentar conexión: WiFi.reconnect() o WiFi.begin() nuevamente.
    • Esperar máximo 5 segundos antes de siguiente intento.
  • Comunicación Serial:
    • Inicialización: Serial.begin(115200) en setup().
    • Debug: Imprimir variables antes de enviar y código HTTP de respuesta.

Plataformas IoT Cloud Recomendadas (Gratuitas)

Puedes usar cualquiera de estas plataformas gratuitas para educación:

🥇 Opción 1: Ubidots STEM (Recomendada)

  • URL: stem.ubidots.com
  • Ventajas: Gratis para siempre (3 dispositivos), dashboards profesionales, alertas por correo.
  • Límite: 4,000 datos/hora por dispositivo.
  • Registro: Usar correo institucional (.edu).

🥈 Opción 2: ThingSpeak (MathWorks)

  • URL: thingspeak.com
  • Ventajas: Integración MATLAB, análisis de datos avanzado.
  • Límite gratuito: 3 millones de mensajes/año (suficiente para el curso).
  • Nota: Crear cuenta gratuita, luego se puede usar indefinidamente con limitaciones.

🥉 Opción 3: Arduino IoT Cloud

  • URL: cloud.arduino.cc
  • Ventajas: Integración nativa ESP32, dashboard sencillo.
  • Límite: 25 días de retención de datos en plan gratuito.

Requisito mínimo independiente de la plataforma:

  • Dashboard con 3 widgets/gráficos (Temperatura, Humedad, Luz).
  • Actualización en tiempo real (cada 15-20 segundos).
  • Acceso público o link compartible para el docente.

✅ Lista de Verificación Pre-Entrega

Antes de enviar tu E3, verifica cada ítem:

  • ☐ El código incluye WiFi.mode(WIFI_STA) y conecta a tu red WiFi
  • ☐ El Monitor Serial muestra "WiFi conectado" y la IP asignada (ej: 192.168.1.45)
  • ☐ Se ven mensajes "Enviando datos..." y "Datos enviados! Código: 200" cada 20 segundos
  • ☐ El Dashboard en la nube muestra datos actualizándose en tiempo real
  • ☐ Hay mínimo 3 widgets/gráficos: Temperatura, Humedad, Luz
  • ☐ Se usa millis() en lugar de delay() para la temporización
  • ☐ El código maneja reconexión automática si se pierde WiFi
  • ☐ El archivo se llama E3_Apellido_Nombre.ino
  • ☐ El link al dashboard es accesible públicamente (no requiere login)
⚠️ Errores Comunes a Evitar:
  • Usar delay(20000) en lugar de millis() (bloquea el sistema)
  • Olvidar llamar http.end() después de cada envío (fuga de memoria)
  • No verificar WiFi.status() antes de enviar (causa errores HTTP)
  • API Key incorrecta o canal no configurado en ThingSpeak/Ubidots
  • Enviar datos más rápido que el límite de la plataforma (15-20 segundos mínimo)
