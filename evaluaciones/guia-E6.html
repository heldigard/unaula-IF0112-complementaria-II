Fase 6 del Proyecto SMAI: Normalización y estandarización - Producto final integrado

Objetivo

Demostrar la integración total de todas las fases del curso en un producto funcional, robusto y estéticamente terminado que solucione un problema real de monitoreo ambiental.

📋 Prerrequisitos (Integración E1-E5)

Para la sustentación final debes presentar:

  • E1: Arquitectura documentada (foto del diagrama de bloques).
  • E2: Circuito físico montado y funcionando.
  • E3: Conectividad WiFi activa y enviando datos a la nube.
  • E4: Lógica de control con máquina de estados implementada.
  • E5: Documentación normativa completa (PDF entregado).

Nota: E6 es la integración y presentación de todo el trabajo anterior. No se desarrolla nuevo código, se perfecciona y encapsula lo existente.

Requisitos del Producto Final

El SMAI debe presentarse como un producto de ingeniería completo, cumpliendo estándares profesionales:

  • Integración Hardware (Herencia de E1-E5):
    • Circuito funcional con ESP32, DHT22 (GPIO 4) y LDR (GPIO 34).
    • Conexión WiFi estable en modo STA.
    • Envío de datos cada 20 segundos a plataforma IoT (Ubidots STEM, ThingSpeak, Arduino Cloud, Blynk y otras opciones gratuitas).
    • Estados de alerta funcionando con LEDs (Rojo: temperatura, Amarillo: luz).
  • Encapsulado y Terminación Física:
    • No cables sueltos: Uso de amarras plásticas o guía de cables.
    • Caja/gabinete de material aislante (plástico ABS, acrílico o madera).
    • Orificios de ventilación para el sensor DHT22 (evitar caja hermética).
    • LEDs visibles desde el exterior o panel frontal.
    • Puerto Micro-USB accesible para alimentación.
  • Funcionamiento Autónomo:
    • Al conectar a 5V, el dispositivo debe iniciar automáticamente.
    • Conexión a WiFi sin intervención manual (credenciales hardcodeadas o modo AP inicial).
    • Tiempo de inicio: Máximo 30 segundos hasta primer envío de datos.
  • Dashboard y Visualización:
    • Dashboard en plataforma IoT gratuita (Ubidots STEM, ThingSpeak, Arduino Cloud, Blynk y otras opciones).
    • Mínimo 3 widgets/gráficos visibles (Temperatura, Humedad, Luz).
    • Opcional: Dashboard en Grafana con alertas configuradas.
    • Historial de datos: Mínimo 1 semana de datos almacenados en la nube.
    • Link compartible o acceso público para el docente.
  • Robustez y Manejo de Errores:
    • Reconexión automática WiFi ante pérdida de señal.
    • Manejo de errores de lectura de sensores (isnan() para DHT22).
    • No bloquearse ante fallos de red (timeout de 10 segundos).
    • Reinicio automático (watchdog) si el sistema se congela.

Lista de Verificación de Calidad (SMAI Final)

Para obtener la nota máxima, el producto debe cumplir con:

  • Organización: Cables trenzados o sujetos con amarras.
  • Aislamiento: La protoboard o PCB debe estar aislada de superficies conductoras.
  • Fuente: El sistema debe encenderse con un cargador de celular estándar (5V) sin depender de la laptop.
  • Sostenibilidad: El código debe implementar el modo Light Sleep del ESP32 entre envíos para ahorro energético (Opcional - Bono).

Entregables Finales

  • Dispositivo físico completo.
  • Repositorio de GitHub con el código final y documentación (README).
  • Ficha técnica final actualizada.
