FASE 1 del Proyecto SMAI: Diseño y planificación técnica

📋 ¿Qué es el SMAI?

SMAI = Sistema de Monitoreo Ambiental Inteligente

Es el proyecto integrador del curso que construirás progresivamente a través de 6 evaluaciones. En E1 diseñarás la arquitectura técnica completa.

Objetivo de Aprendizaje (RA1)

Al finalizar esta evaluación, serás capaz de:

  • Diseñar la arquitectura técnica de un sistema IoT de 4 capas
  • Justificar la selección de hardware basándote en especificaciones técnicas
  • Seleccionar protocolos de comunicación apropiados para el contexto
  • Aplicar conceptos de telecomunicaciones y conectividad

RA Asociado: Brinda conceptos de telecomunicaciones, Internet y conectividad como base para comprender la evolución de la domótica y el Internet de las Cosas

Contenido Obligatorio del Documento

Tu informe en PDF debe contener exactamente estas 4 secciones:

1. Definición del Problema (20% del documento)

Describe el contexto específico donde instalarás tu SMAI. Elige uno de estos escenarios o propón otro:

Ejemplos de Contextos Válidos:

  • Invernadero casero: Monitoreo de temperatura y humedad para optimizar crecimiento de plantas
  • Oficina inteligente: Control ambiental para confort y ahorro energético
  • Habitación del bebé: Vigilancia de condiciones ambientales para seguridad infantil
  • Bodega de vinos: Control climático para preservación de productos
  • Laboratorio escolar: Monitoreo de condiciones para experimentos sensibles

Debes incluir: Ubicación física, problema específico a resolver, variables ambientales críticas (temp, humedad, luz), usuarios beneficiarios.

2. Arquitectura del Sistema (40% del documento)

Dibuja y describe un diagrama de bloques que muestre las 4 capas del modelo IoT aplicadas a tu SMAI:

Plantilla del Diagrama de Bloques:

Para cada capa debes explicar:

  • Capa de Percepción: Sensores DHT22 (GPIO 4) y LDR (GPIO 34, ADC1). Incluye especificaciones técnicas: rango, precisión, voltaje de operación.
  • Capa de Procesamiento: Microcontrolador ESP32 como unidad central. Explica por qué es adecuado vs. otras opciones.
  • Capa de Red: Conectividad WiFi en modo STA (no AP). Protocolo HTTP o MQTT.
  • Capa de Aplicación: Plataforma en la nube. Ver guía completa de plataformas IoT gratuitas →

3. Justificación de Hardware (30% del documento)

Tabla comparativa técnica justificando la selección del ESP32:

Característica ESP32 Arduino Uno Ventaja ESP32
Procesador Dual-core 240 MHz 16 MHz single-core 15x más rápido, multitarea real
RAM 520 KB 2 KB 260x más memoria para datos
Conectividad WiFi + Bluetooth integrados Ninguna (requiere shields) Sin hardware adicional
Precio $6-8 USD $20-25 USD + shield WiFi ($15) 3x más económico con WiFi
Consumo Modos de bajo consumo Consumo fijo Ideal para baterías

Conclusión obligatoria: Explica por qué el ESP32 es la mejor opción para tu aplicación específica de monitoreo ambiental.

4. Plan de Conectividad (10% del documento)

Describe tu estrategia de comunicación:

  • Protocolo: ¿HTTP GET o MQTT? ¿Por qué?
  • Frecuencia: ¿Cada cuántos segundos enviarás datos? (Recomendado: 15-20 segundos)
  • Formato: ¿Qué datos enviarás? (ej: temperatura, humedad, luz)
  • Seguridad: ¿Cómo protegerás las credenciales WiFi?

Ejemplo de Plan de Conectividad:

Protocolo: HTTP GET por simplicidad y compatibilidad con ThingSpeak

Frecuencia: 20 segundos (cumple con límites de cuenta gratuita y es suficiente para monitoreo ambiental)

Formato: api.thingspeak.com/update?api_key=XXX&field1=temp&field2=hum&field3=luz

Seguridad: Credenciales almacenadas en variables constantes en código (limitación aceptable para proyecto académico)
