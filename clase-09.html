🖥️ IT vs OT: Dos Mundos Convergiendo

🎯 Aprendizaje Clave

IT (Tecnología de la Información) gestiona datos y sistemas de negocio. OT (Tecnología Operacional) controla equipos y procesos físicos. IoT es el puente que une ambos mundos.

🖥️ IT (Information Technology)

  • 💻 Computadoras
  • 🌐 Redes de datos
  • 📊 Software empresarial
  • ☁️ Computación en la nube
  • 🔒 Seguridad informática
  • 📱 Aplicaciones móviles

🏭 OT (Operational Technology)

  • 🏭 Máquinas industriales
  • 🔧 Sensores de campo
  • ⚡ Sistemas de control
  • 🤖 PLCs y SCADA
  • 🎛️ Instrumentación
  • ⚙️ Robótica industrial

📡 IoT: El Puente de Convergencia

El Internet de las Cosas actúa como el puente que une estos dos mundos tradicionalmente aislados, permitiendo que los datos operacionales fluyan hacia los sistemas de información y viceversa.

❓ ¿Por qué es importante la Convergencia IT/OT?

La Industria 4.0 requiere que los sistemas de información (IT) y los sistemas operacionales (OT) trabajen juntos de manera integrada. Esta convergencia no es solo tecnológica, sino también cultural y organizacional.

Ejemplos del Mundo Real

🏭 Manufactura

Sensores en maquinaria envían datos a sistemas ERP para planificación de mantenimiento predictivo, optimización de producción y gestión de inventario en tiempo real.

⚡ Energía

Smart grids conectan plantas generadoras con sistemas de facturación y análisis de demanda, permitiendo una distribución más eficiente de la energía eléctrica.

📦 Logística

Tracking de flotas integrado con sistemas de inventario permite optimizar rutas, predecir tiempos de entrega y reducir costos operativos.

⚠️ Desafío Cultural

La convergencia IT/OT requiere superar barreras culturales: los equipos de IT priorizan la seguridad y los cambios rápidos, mientras que OT prioriza la estabilidad y evita alterar sistemas que funcionan.

🌉 IoT: El Puente entre IT y OT

Antes: Mundos Aislados (Silos)

❌ Problemas del Modelo Tradicional

  • IT y OT operaban completamente separados
  • Los datos de planta no llegaban a los sistemas de negocio
  • Decisiones basadas en información desactualizada
  • Duplicación de esfuerzos y recursos
  • Visibilidad limitada de la operación

Después: Convergencia mediante IoT

✅ Beneficios de la Convergencia

  • Visibilidad unificada: Dashboards integrados con datos de toda la operación
  • Análisis conjunto: Datos operacionales cruzados con información de negocio
  • Automatización end-to-end: Desde el sensor hasta el ERP
  • Mejores decisiones: Basadas en datos en tiempo real
  • Optimización continua: ML/AI aplicados a datos operacionales

☁️ Cloud Computing para IoT

🎯 Aprendizaje Clave

El Cloud Computing ofrece recursos ilimitados para análisis histórico y ML, pero introduce latencia (100-500ms) y dependencia de Internet.

El Cloud Computing es el modelo de computación donde los recursos (servidores, almacenamiento, bases de datos, software) se entregan a través de Internet mediante un modelo de pago por uso.

Arquitectura Centralizada

☁️ NUBE (Cloud Layer)

Almacenamiento masivo Procesamiento distribuido Machine Learning Dashboards APIs

✅ Ventajas del Cloud

  • Escala infinita según demanda
  • Recursos computacionales ilimitados
  • Sin mantenimiento de hardware
  • ML/AI avanzado disponible
  • Acceso desde cualquier lugar
  • Copias de seguridad automáticas
  • Redundancia geográfica

❌ Desventajas del Cloud

  • Alta latencia (100-500ms típico)
  • Dependencia total de Internet
  • Costos crecen con el uso
  • Preocupaciones de privacidad
  • Transferencia de datos costosa
  • Menor control sobre infraestructura

⚡ Edge Computing

🎯 Aprendizaje Clave

El Edge Computing procesa datos cerca de su fuente, reduciendo latencia a 1-10ms y permitiendo operación sin Internet. Esencial para aplicaciones críticas.

El Edge Computing es el paradigma de procesamiento donde los datos se procesan cerca de su fuente (en el "borde" de la red), en lugar de enviarlos a un centro de datos centralizado.

🎯 Definición

"Procesamiento de datos cerca de la fuente que los genera, reduciendo la latencia y el tráfico de red"

Flujo de Datos en Edge Computing

🔧 DISPOSITIVOS (Device Layer)

Sensores Actuadores Cámaras Medidores

⚡ EDGE (Edge Layer)

Filtrado de datos Agregación Decisiones locales Gateway

☁️ CLOUD (Cloud Layer)

Solo datos relevantes Análisis histórico ML training

Dispositivos Edge Comunes

Dispositivo Uso típico Capacidad
Raspberry Pi Prototipos, gateways ligeros Media
Intel NUC Edge industrial Alta
NVIDIA Jetson AI en el edge GPU integrada
Gateways industriales Fábricas, robustez Variable

⏱️ Edge vs Cloud: Comparación de Latencia

Métrica ⚡ EDGE ☁️ CLOUD
Latencia típica 1-10 ms 100-500 ms
Ruta de datos Sensor → Edge Sensor → Edge → Internet → Cloud
Dependencia red Mínima Total
Procesamiento Local, inmediato Remoto, con delay

🚨 Casos Críticos que Requieren Edge

🚗 Vehículos Autónomos

Latencia requerida: < 10ms
Una decisión de frenado no puede esperar 200ms de ida y vuelta a la nube. Debe procesarse localmente en el vehículo.

🏭 Control Industrial

Latencia requerida: < 50ms
Los sistemas de control de líneas de producción requieren respuestas inmediatas para mantener calidad y seguridad.

🏥 Monitoreo Médico

Latencia preferida: < 100ms
Dispositivos médicos críticos deben alertar anomalías inmediatamente, sin depender de la conectividad.

🌫️ Fog Computing

🎯 Aprendizaje Clave

El Fog Computing es una capa intermedia entre Edge y Cloud, distribuyendo computación en nodos locales (routers, servidores) para reducir latencia a 10-50ms.

El Fog Computing extiende los servicios de la nube hasta el borde de la red, creando una capa intermedia distribuida entre los dispositivos y la nube central.

🌫️ Definición

"Nube extendida hasta el edge - una capa de computación distribuida que reduce la distancia entre datos y procesamiento"

Jerarquía de Fog Computing

☁️ CLOUD (Nube Central)

Análisis global, ML training, almacenamiento a largo plazo

🌫️ FOG LAYER (Nodos Distribuidos)

Routers inteligentes, servidores locales, micro-datacenters

Fog Node 1 (Router) Fog Node 2 (Servidor) Fog Node 3 (Mini DC)

⚡ EDGE DEVICES

Gateways locales, dispositivos de borde

Cloud vs Fog vs Edge

Característica Cloud Fog Edge
Ubicación Centros de datos remotos Red local / cercana Dispositivo / gateway
Latencia 100-500ms 10-50ms 1-10ms
Capacidad Ilimitada Media Limitada
Cobertura Global Regional/Local Local/Punto

❓ ¿Cuándo Usar Edge vs Cloud?

✅ Usar EDGE cuando:

  • La latencia es crítica (< 100ms)
  • Se requiere operación sin Internet
  • El volumen de datos es muy alto
  • Los datos son sensibles/privados
  • Los costos de transferencia son altos
  • Se necesitan decisiones locales inmediatas
  • El ancho de banda es limitado

☁️ Usar CLOUD cuando:

  • Se necesita análisis histórico a largo plazo
  • El Machine Learning es complejo
  • Se requiere visualización centralizada
  • Hay integración multi-sitio
  • Se necesitan recursos computacionales altos
  • El almacenamiento masivo es necesario
  • Se requiere escala elástica

💡 Mejor Práctica: Arquitectura Híbrida

🎯 La mayoría de proyectos IoT exitosos usan ambos

  • Edge: Procesamiento en tiempo real, decisiones críticas, filtrado
  • Cloud: Análisis histórico, ML, dashboards, integración empresarial

Regla de oro: Procesa en el edge lo que necesites inmediatamente, envía a la nube lo que necesites analizar.

🔌 Gateway IoT

🎯 Aprendizaje Clave

El Gateway IoT es el puente crítico entre OT e IT: traduce protocolos, filtra datos, almacena localmente y asegura la comunicación entre dispositivos y nube.

El Gateway IoT es el dispositivo puente que conecta los dispositivos de borde con la nube, realizando funciones críticas de traducción, preprocesamiento y seguridad.

Funciones del Gateway

1️⃣ Traducción de Protocolos

Convierte protocolos de OT (Zigbee, Modbus, OPC UA) a protocolos de IT (MQTT, HTTP, HTTPS)

// Ejemplo: Modbus → MQTT
Sensor (Modbus RTU) → Gateway → Cloud (MQTT over TLS)
  [OT Protocol]      [Translate]      [IT Protocol]

2️⃣ Preprocesamiento

  • Filtrado: Elimina lecturas erróneas y ruido
  • Agregación: Resume datos (promedios, máximos)
  • Normalización: Estandariza formatos de datos

3️⃣ Almacenamiento Local (Buffer)

Mantiene datos cuando no hay conexión a Internet, sincronizando cuando se restablece.

4️⃣ Seguridad

  • Firewall de red
  • Cifrado TLS/SSL
  • Autenticación de dispositivos
  • Aislamiento de redes OT/IT

Hardware Típico de Gateway

Dispositivo Aplicación Características
Raspberry Pi 4 Prototipos, pequeñas instalaciones Económico, flexible, comunidad activa
Intel NUC Edge industrial Alto rendimiento, Windows/Linux
Gateway Industrial (Advantech, etc.) Fábricas, entornos hostiles Robusto, certificaciones industriales

Ejemplo: Filtrado y Agregación en Edge

// FILTRADO - Eliminar ruido con promedio móvil
float filtrarLecturas(float nuevaLectura) {
    static float buffer[5];
    static int indice = 0;
    
    buffer[indice] = nuevaLectura;
    indice = (indice + 1) % 5;
    
    // Promedio móvil
    float suma = 0;
    for (int i = 0; i < 5; i++) suma += buffer[i];
    return suma / 5;
}
// AGREGACIÓN - Resumir datos antes de enviar
void enviarResumen() {
    static float minTemp = 100, maxTemp = -100, sumaTemp = 0;
    static int conteo = 0;
    
    // Cada 60 segundos, enviar resumen en lugar de 60 lecturas
    if (conteo >= 60) {
        float promedio = sumaTemp / conteo;
        enviarACloud(minTemp, maxTemp, promedio, conteo);
        
        // Reset para siguiente ciclo
        minTemp = 100; 
        maxTemp = -100; 
        sumaTemp = 0; 
        conteo = 0;
    }
}

    temps = [d['temperatura'] for d in datos]

🔮 Digital Twin (Gemelo Digital)

Un Digital Twin es una réplica digital de un objeto, proceso o sistema físico, que se actualiza en tiempo real con datos del mundo real y permite simular, predecir y optimizar.

🎯 Definición

"Réplica digital de un objeto físico que utiliza datos en tiempo real para simular, predecir y optimizar el comportamiento del sistema"

Componentes del Digital Twin

🏭 Mundo Físico

  • Máquina real
  • Sensores físicos
  • Actuadores
  • Ambiente operativo

💻 Mundo Digital

  • Modelo matemático 3D
  • Base de datos en tiempo real
  • Simulación y análisis
  • Predicción y optimización

Aplicaciones del Digital Twin

Aplicación Descripción Beneficio
Mantenimiento predictivo Predecir fallas antes de que ocurran -40% tiempo de parada
Diseño virtual Probar cambios sin afectar producción Menor riesgo, menor costo
Entrenamiento Capacitar operadores en simulador Seguridad, repetibilidad
Optimización Encontrar mejores parámetros de operación +15-20% eficiencia

⚠️ Requisitos para Implementar Digital Twin

  • Conectividad robusta entre físico y digital
  • Modelos matemáticos precisos
  • Datos históricos para calibración
  • Capacidad computacional para simulación
  • Integración IT/OT completa
