Contexto y motivacion

En IoT no solo importan los dispositivos, sino la forma en que interactuan. Las conexiones P2M, M2M, M2P y P2P definen el flujo de control, los tiempos de respuesta y el nivel de autonomia. Identificar el tipo de conexion permite diseñar arquitecturas eficientes y seguras.

Idea clave: cambia el actor que inicia la accion y cambia el diseño completo del sistema.

Clasificacion de conexiones

Aprendizaje clave

Los 4 patrones de conexión IoT son: P2M (Persona controla máquina), M2P (Máquina notifica persona), M2M (Máquina con máquina), y P2P (Persona con persona). Cada patrón tiene latencia, complejidad y confianza diferentes.

Persona (P) Maquina (M) | | | | +---+---+ +---+---+ | | | | P2M M2P M2M P2P

P2M (Persona a Maquina)

Un humano controla o interactua directamente con un dispositivo IoT.

Caso P → M Descripcion
Smart Home App enciende luz Usuario toca boton en app
Vehiculo Conductor activa calefaccion Boton fisico en panel
Industrial Operario ajusta parametros HMI panel tactil
Wearable Usuario consulta reloj Tap en pantalla
  • Latencia: < 100 ms (feedback inmediato).
  • Confianza: alta (humano en el loop).
  • Complejidad: baja.
// App envia comando al ESP32
void loop() {
  if (Serial.available()) {
    char comando = Serial.read();
    if (comando == '1') {
      digitalWrite(LED_PIN, HIGH); // Encender luz
    }
  }
}

M2M (Máquina a Máquina)

Dispositivos IoT se comunican sin intervencion humana.

Caso M → M Descripcion
Domotica Sensor movimiento → Camara Movimiento detectado activa grabacion
Industrial Sensor vibracion → Motor Vibracion alta apaga motor
Agricultura Sensor humedad → Valvula Suelo seco abre riego
Smart Grid Medidor → Interruptor Demanda alta reduce carga
  • Latencia: variable (ms a segundos).
  • Autonomia: completa.
  • Complejidad: media-alta.
// ESP32 (M1) publica, ESP32 (M2) recibe y actua
// Emisor (M1)
void loop() {
  float temp = dht.readTemperature();
  if (temp > 30) {
    client.publish("casa/living/alerta", "TEMP_ALTA");
  }
}

// Receptor (M2)
void callback(char* topic, byte* payload, unsigned int length) {
  if (strcmp((char*)payload, "TEMP_ALTA") == 0) {
    digitalWrite(AIRE_PIN, HIGH); // Encender A/C
  }
}

M2P (Máquina a Persona)

El dispositivo notifica o entrega informacion al humano.

Caso M → P Descripcion
Wearable Reloj → Usuario Alerta de frecuencia cardiaca
Smart Home Sensor → App Notificacion "Puerta abierta"
Industrial Maquina → Operario "Mantenimiento requerido"
Smart City Semaforo → Conductor "Luz roja en 10s"
  • Latencia: segundos aceptable.
  • Formato: push, email, dashboard.
  • Confianza: media (requiere verificacion).
// ESP32 notifica al usuario via Push
void enviarNotificacionPush(String mensaje) {
  HTTPClient http;
  http.begin("https://push.example.com/api");
  http.addHeader("Content-Type", "application/json");

  String payload = "{\"message\":\"" + mensaje + "\"}";
  int httpCode = http.POST(payload);

  http.end();
}

void loop() {
  if (alguienDetectada()) {
    enviarNotificacionPush("Movimiento en sala");
  }
}

P2P (Persona a Persona vía IoT)

Personas se comunican mediadas por infraestructura IoT.

Caso P → [IoT] → P Descripcion
Telemedicina Paciente → Cloud → Doctor Datos vitales transmitidos
Adulto mayor Abuelo → Alerta → Familia Caida detectada
Colaborativo Usuario 1 → Shared → Usuario 2 Edificio compartido
Social Jugador → Plataforma → Amigos Videojuego AR
  • Latencia: baja (< 1 s para inmediatez).
  • Interactividad: bidireccional.
  • Enriquecimiento: datos contextuales.
// Paciente (P1) -> Cloud -> Doctor (P2)
void enviarVitals() {
  String payload = "{\"hr\":85, \"spo2\":98, \"temp\":36.5}";
  client.publish("paciente/123/vitals", payload);
}

// Receptor (P2 - Doctor dashboard)
void callback(char* topic, byte* payload, unsigned int length) {
  StaticJsonDocument<200> doc;
  deserializeJson(doc, payload);

  int hr = doc["hr"];
  displayHeartRate(patientID, hr);
}

⚖️ Marco Legal IoT: Ley 1581 de 2012

⚠️ Importante para E5

Esta sección prepara para E5 (15%) que evalúa el marco metodológico y legal regulatorio. La Ley 1581 es fundamental para proyectos IoT que manejan datos personales.

¿Qué es la Ley 1581?

La Ley 1581 de 2012 es la norma colombiana de protección de datos personales. Establece derechos y obligaciones para el tratamiento de datos.

Datos Personales en IoT

Tipo Ejemplos IoT Consideración
Identificación Nombre, email, ID usuario Siempre personal
Ubicación GPS, dirección IP Puede identificar patrones
Biométricos Huella, ritmo cardíaco Datos sensibles
Técnicos MAC, IMEI, ID dispositivo Pueden vincularse a usuario

Derechos ARCO

Derecho Significado Ejemplo IoT
A - Acceso Saber qué datos se tienen Ver historial de sensores
R - Rectificación Corregir datos incorrectos Actualizar email contacto
C - Cancelación Eliminar datos personales Borrar historial ubicación
O - Oposición Negarse al tratamiento No compartir con terceros

Obligaciones para Proyectos IoT

  • Consentimiento: Obtener autorización previa del usuario.
  • Política de privacidad: Documento público y accesible.
  • Seguridad: Proteger datos contra acceso no autorizado.
  • Minimización: Recolectar solo lo necesario.
