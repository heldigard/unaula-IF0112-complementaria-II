Resumen ejecutivo para desarrolladores

Aprendizaje clave

En IoT, casi todo puede volverse dato personal: ubicación, horarios de uso, temperatura ambiente (presencia), hábitos de consumo. La Ley 1581 exige: consentimiento previo, políticas de privacidad, derechos ARCO (Acceso, Rectificación, Cancelación, Oposición), y seguridad mínima (encriptación, control de acceso).

Si tu proyecto IoT captura datos personales en Colombia, debes cumplir la Ley 1581 de 2012. Esta ley exige consentimiento previo, politicas de privacidad claras y la implementacion efectiva de derechos ARCO.

Idea clave: en IoT, casi todo puede volverse dato personal si permite inferir habitos o identificar personas.

Que datos se consideran personales

Un dato es personal si identifica o puede identificar a una persona. En IoT, incluso datos "ambientales" pueden ser personales por inferencia.

Tipo Dato IoT ¿Es personal?
Ubicacion GPS del dispositivo Si
Uso Horarios de encendido Si (patron de vida)
Ambiente Temperatura habitacion Si (inferencia presencia)
Biometricos Huella, voz Si (sensibles)
Salud Frecuencia cardiaca Si (dato especial)
Consumo Uso energia Si (habitos)
Agregado Promedio de zona No (no identifica individuo)

Obligaciones principales

1. Politica de privacidad

  • Que datos se capturan y por que.
  • Con quien se comparten.
  • Como se protegen.
# Politica de Privacidad - Termostato Inteligente

## Datos Capturamos
- Temperatura configurada por el usuario
- Horarios de uso (encendido/apagado)
- Ubicacion del dispositivo (solo casa)

## No Capturamos
- Audio, video
- Datos de otros dispositivos
- Conversaciones

## Como Protegemos
- Encriptacion TLS 1.3 en transito
- Almacenamiento cifrado (AES-256)
- Acceso limitado al equipo

## Sus Derechos (ARCO)
Puede solicitar Acceso, Rectificacion, Cancelacion u Oposicion
escribiendo a privacidad@ejemplo.com

2. Autorizacion (consentimiento)

  • Previa: antes de capturar datos.
  • Informada: el usuario sabe que entrega.
  • Explicita: opt-in, no opt-out.

Derechos ARCO: implementacion tecnica

Acceso (A)

// GET /api/v1/user/data
// Response 200
{
  "user_id": "user_123",
  "data_collected": {
    "temperature_readings": 1520,
    "schedule": {"mon": [{"start": "07:00", "end": "23:00"}]},
    "device_location": "Medellin"
  },
  "retention_period": "90 days"
}

Rectificacion (R)

// PUT /api/v1/user/data/profile
{
  "field": "email",
  "old_value": "old@email.com",
  "new_value": "new@email.com",
  "reason": "Email actualizado"
}

Cancelacion / Supresion (C)

// DELETE /api/v1/user/data
// Response 200
{
  "status": "deleted",
  "data_deleted": 1520,
  "data_retained": ["billing_records"],
  "retained_reason": "legal_requirement"
}

Oposicion (O)

// POST /api/v1/user/consent
{
  "data_type": "location",
  "purpose": "third_party_sharing",
  "consent": false
}

Seguridad minima obligatoria

  • Encriptacion en transito (TLS 1.2+).
  • Encriptacion en reposo (AES-256 equivalente).
  • Control de acceso y autenticacion.
  • Auditoria y logs de accesos.
Deber de informar: vulnerabilidades que afecten datos personales deben reportarse a la SIC en 15 dias habiles.

Sanciones

Infraccion Sancion maxima
No informar politica Multa hasta 300 SMMLV
No obtener autorizacion Multa hasta 600 SMMLV
No cumplir ARCO Multa hasta 1000 SMMLV
Comprometer seguridad Multa hasta 1000 SMMLV + cierre

Referencia: 1 SMMLV 2025 ≈ 260 USD (aprox).

Checklist de cumplimiento

  • Politica de privacidad redactada y publicada.
  • Consentimiento explicito implementado.
  • API ARCO implementada (A, R, C, O).
  • Encriptacion TLS 1.3 habilitada.
  • Encriptacion at-rest configurada.
  • Logs de auditoria activados.
  • Procedimiento de retencion definido.
  • Minimizacion de datos aplicada.

Actualización importante (2025)

Proyecto de Reforma Ley 1581 (Agosto 2025)

Nota importante: En agosto de 2025, se presentó un proyecto de ley para modernizar y actualizar la Ley 1581 de 2012. Esta reforma propuesta incluye:

  • Adaptación a estándares internacionales: Alineación con el GDPR europeo y CCPA californiano.
  • Mayor autonomía del titular: Fortalecimiento de los derechos ARCO y adición de nuevos derechos (portabilidad, oposición automatizada).
  • Notificación de incidentes: Plazos más estrictos (72 horas para incidentes graves, reduciendo los 15 días actuales).
  • Principios de privacidad por diseño: Obligación de incorporar protección de datos desde el diseño de sistemas IoT.
  • Evaluaciones de impacto: Requerimiento de DPIA (Data Protection Impact Assessment) para proyectos de alto riesgo.
  • Sanciones actualizadas: Montos proporcionales a la gravedad y facturación de las empresas.

Estado: Proyecto en trámite legislativo (pendiente de aprobación al 2026-I). Mientras se aprueba, la Ley 1581 de 2012 sigue vigente en su versión original.

Recomendación: Diseñar sus proyectos IoT cumpliendo los estándares más altos (GDPR + reforma propuesta) para estar preparados cuando entre en vigencia.

Fuente: Congreso de la República de Colombia, Proyecto de Ley número 318 de 2025 Senado / 397 de 2025 Cámara.
