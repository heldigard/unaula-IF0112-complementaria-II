Requisitos del SMAI Final

  • Hardware: ESP32 montado firmemente con sus sensores (DHT22 / LDR)
  • Encapsulado: El dispositivo no debe tener cables sueltos (usar caja, gabinete o soporte)
  • Conectividad: WiFi estable enviando datos a la API propia (FastAPI o MQTT)
  • API + BD: FastAPI local (o broker MQTT + subscriber) con base de datos SQLite/MySQL
  • Visualización: Dashboard web propio (HTML+JS), Grafana, o interfaz que consuma la API

Recuerda: E6 es la entrega final del proyecto, presentada con sustentación oral y demo en vivo. Puedes usar FastAPI + BD o MQTT + BD. ThingSpeak y Ubidots son opcionales, no requisito.

Plan B: Video de Emergencia

Si el día de la sustentación falla algo crítico (red, hardware, laptop), el video de respaldo te salva. Grábalo antes del 23 de mayo y guárdalo en la laptop y en el celular de un compañero.

Instrucciones para grabar el video (máx. 3 min)

  1. 0:00-0:30: Mostrar el ESP32 encendido y enviando datos (Monitor Serial o dashboard).
  2. 0:30-1:30: Navegar por la API: mostrar /docs, hacer POST de prueba, luego GET /datos/latest.
  3. 1:30-2:15: Mostrar la base de datos con datos históricos (tabla con timestamps reales).
  4. 2:15-3:00: Mostrar el dashboard actualizándose o el gráfico de datos.

Regla de oro: El video debe tener datos en movimiento, no screenshots estáticos. Si algo falla en vivo, muestras el video y explicas qué pasó.

Tarjetas de Rescate: Si algo falla en vivo

🔴 ESP32 no conecta a WiFi

  1. Revisar que red y contraseña estén bien en el código.
  2. Usar hotspot del celular con la misma SSID/contraseña.
  3. Reiniciar ESP32 (botón EN).
  4. Si persiste: mostrar video de emergencia.

🟡 API no responde / error CORS

  1. Verificar que la API corre: http://127.0.0.1:8000/docs.
  2. Revisar IP en el dashboard: ¿coincide con la IP de la laptop?
  3. Confirmar CORS habilitado en main.py.
  4. Plan B: abrir Swagger UI y mostrar los endpoints funcionando.

🔵 Dashboard muestra "--" o no carga

  1. Abrir consola del navegador (F12 → Network) y ver errores.
  2. Probar URL directa de la API en el navegador.
  3. Si el JS falla: refrescar con Ctrl+F5.
  4. Plan B: mostrar datos directamente desde SQLite/DB Browser.

🟢 Se cayó un cable o sensor

  1. No entrar en pánico. Decir: "Vamos a reconectar el cable."
  2. Reconectar con la laptop visible al jurado.
  3. Mientras tanto, otro compañero explica la arquitectura.
  4. Reiniciar ESP32 y continuar la demo.
